# FilterFlip-RAG GUI v2.8

10 November 2026. A separate release with an expanded recorded-findings explorer and security hardening. v2.7.2, its acceptance and all original research evidence remain preserved.

## First launch

Extract into a new folder. Stop the old demo server with Ctrl+C. Open a terminal in the new release folder:

```bash
conda activate filterflip-core
python3 -B tools/verify_packet.py
python3 -B app/configure.py --from-config "/absolute/path/to/your/working/config.local.json" --work "$HOME/FilterFlip_v28_work"
python3 -B app/launch.py "$HOME/FilterFlip_v28_work/config.local.json"
```

Replace only the existing-config placeholder with your actual working configuration path. The new work folder must not already exist. This imports its asset locations and creates an owner-only configuration and a separate private run archive. It does not alter the old configuration or download any models. Existing pinned CPU assets are required.

Open **http://127.0.0.1:8767** and refresh the page. Subsequent launches need only the environment activation and last launch command.

Keep configuration, logs and runs outside this extracted release. The launcher now checks configuration ownership, permissions and its parent directory. Use the configuration helper above if an older hand-copied file is rejected; do not weaken the checks. Use `python3 -B` so generated bytecode does not enter the sealed application folder.

## What changed

“Findings and Evidence” now has seven expandable sections: primary finding, copy variants, reproduction, mitigation, security challenges, recorded TrustRAG stage 1, and application security. It includes an explorer for all 12 TrustRAG cases under C/BN1/PN1, exact saved paired answers, support judgments and expandable passages. U means unfiltered; T means TrustRAG stage 1.

The live modes and their scientific settings remain the same. TrustRAG is a **recorded evidence view**, not a new live-generation mode or a full-defense comparison. No new research answers were generated to prepare this release.

Other changes: private config validation, verification/execution of the same retrieval-script bytes, private rotating security-event logs, an exclusive run-archive lock, explicit offline archiving, clearer verification errors, extra browser headers and consistent malformed-cancel responses.

Read `VALIDATION_REPORT.md` for current developer checks, `REVIEW_DISPOSITION.md` for the assessment response, and `ACCEPTANCE_CHECKLIST.md` for the independent acceptance tasks. Earlier validation/acceptance folders describe historical releases and do not automatically accept v2.8.

Review this new version separately. Earlier research outcomes and release acceptances remain preserved. Record the actual reviewer, date, environment and observations; do not pre-fill acceptance.

1. Follow START_HERE.md in a new extracted folder. Save packet verification output and environment details. Keep your previous release/config unchanged.
2. Create the new external work folder with the helper. Verify normal startup; confirm configuration stays outside the release. If checking rejected permissions, use a disposable config copy and restore it afterwards.
3. Open Findings and Evidence. Check all seven sections; compare the 8/59 primary result, nine conditions, reproduction caveats, mitigation gains/losses and challenge harms against accepted records.
4. In recorded TrustRAG, select several cases including Heather and cornflakes. Open C/BN1/PN1, answers, support judgments and full passages. Confirm this is clearly saved stage-1 evidence and does not launch a model. Cross-check the uncertain case and limitations.
5. Use a primary-case link to the nine-condition explorer; compare reference and reproduction answers. Confirm uncertainty, missing review and truncation remain visible.
6. Run the existing live modes if doing a fresh live acceptance: original, copy variants, mitigation and challenge. Export each run and note the question, condition, environment, completion/failure and elapsed time. New answers need separate interpretation; an operational pass is not a semantic judgment. CPU runs can take several minutes.
7. On a disposable synthetic/test work folder, check private security-event creation and the archive preview/apply procedure. Never archive a running job or edit evidence to make it eligible. Preserve the archive receipt.
8. Optionally reproduce offline checks from VALIDATION_REPORT.md. Save full logs, including failures. The browser script requires Playwright and Chrome and uses synthetic output; it is not fresh model acceptance.
9. Return a short pass/fail/not-run table with exact commands, observed defects, exports and logs. State whether you accept the GUI changes and list limitations separately. Do not include local configuration, model files or tokens in a shared review ZIP.

No sign-off or joint adjudication is assumed by this checklist.

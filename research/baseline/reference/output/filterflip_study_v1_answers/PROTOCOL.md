# FilterFlip: paired answer stage

This stage includes all 59 frozen eligible questions, nine corpus conditions and both unfiltered/filtered contexts: 1,062 logical answer conditions. Source review remains partial (24 user-recorded assisted reviews, 35 assistant-only). No new exclusions or source-label edits are made. Use the unchanged saved retrieval and native-filter outputs. Model inputs contain the question and text in saved order; no expected answers, labels, document provenance, removal decisions or reviewer names are supplied to the model.

Use the existing local Ollama 0.34.2, Qwen2.5:3b digest 357c53fb659c5076de1d65ccb0b397446227b71a42be9d1603d46168015c9e4b. Preserve the earlier evidence-only system prompt literally, temperature 0, seed 42, num_ctx 4096, num_predict 128. The exact prompt and every request are hashed before study calls. All API requests are fixed to 127.0.0.1:11434, with proxy use disabled; no paid API, download or external endpoint is used. No server/model settings are changed.

## Context-window checks

Obtain the existing GGUF vocabulary and merges from the local model's verbose metadata. Construct the installed Qwen2 tokenizer using these assets (not the MiniLM tokenizer). Count the simple system+user ChatML template rendered by this model, preserving content. Check it once on a synthetic non-study request; retain the complete probe. Require estimated prompt tokens + 128 output tokens + 64 safety tokens <=4096 for every planned request. Record the server's prompt counts and stop for review if they differ from the estimate by over 16 tokens, or if the budget is exceeded. No truncation, shortening or prompt rewriting to obtain desirable answers. The safety margin and count tolerance address template-accounting differences, not permission to truncate.

## Execution and exact-request reuse

Run C, BN1 and PN1 for every question first, then all remaining predeclared conditions for every question. For each condition preserve both unfiltered and filtered logical rows. Compute a hash of the entire actual API request. Requests that are byte-equivalent under canonical JSON reuse the first saved result, with the original call ID and reuse flag retained. Different passage text/order or questions produce different requests. This saves runtime; reused outputs are not independent confirmations, and deterministic settings do not prove bit-identical responses across all future reruns.

Save a durable pending marker before each unique request, then its raw response and timing. Faults, empty responses, length truncation and token-budget discrepancies stop the run for inspection, with no automatic retry. An explicit resume may execute only unattempted requests under the same hashes; a pending marker from an interrupted request requires review. Keep unsuccessful attempts, not just successful outputs. A run is complete only when every planned logical condition resolves to an acceptable response. A response status of ok means API completion only, never correctness or groundedness.

## Evaluation

Retain expected answers and historical/source-specific qualifications outside the prompt. Distinguish abstention, wrong answer, incomplete answer, supported correct answer and correct-looking answer without sufficient context evidence. Exact strings are screening aids only, especially for compound answers, aliases and relation questions. The prior assistant semantic triage of 16 quotation-loss flags is not independent human validation and does not establish all other cases as non-events. Review decisive paired responses against all actual surviving passages. Do not infer support from model recall, an answer token alone, a qrel or target-document identity.

The strict primary event remains the frozen PN1 endpoint: a clean grounded correct answer with sufficient filtered evidence; an exposed copy and sufficient PN1 pre-filter evidence; a correct grounded unfiltered answer; insufficient evidence after filtering; and failure to provide a usable grounded filtered answer. Report abstention/wrong-answer changes separately from unsupported correct-looking answers. BN1 retention/correctness is a stricter control-qualified subset, not a reason to erase unqualified cases. Keep clean failures, exposure misses and incomplete cases in their declared denominators. No final attack-success rate, publication-novelty conclusion or general robustness claim is justified by automatically counted strings. Decisive events and the preselected non-event sample still need human verification.
